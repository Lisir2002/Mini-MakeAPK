# Brainstorm Phase 1 — Free Ideation

> 项目：**Web2APK**（纯安卓 App，把网页/前端代码 HTML/PHP/Vue/URL 一键生成 APK）
> 约束：设计语言已锁定（可爱简约·iOS·色彩单调，`PROJECT_BRIEF.md` §3）；目标用户全年龄段、核心感受"舒适"。
> 议题：构建策略、MVP 范围、输入方式优先级。

## 各角色原始想法（Phase 1，不过滤）

### Kira（产品设计师）
1. **"三秒上手"首屏**：打开 App 只有一个大圆角输入框 + 一个珊瑚粉胶囊按钮"变成 App ↘"，零菜单、零恐吓。
2. **打包进度可爱化**：构建不是转圈，而是一只小图标在"织"一个 App，完成时"砰"地弹出成果庆祝（spring 回弹）。
3. **输入即预览**：粘贴 URL/HTML 后右侧即时 WebView 预览，所见即所得，降低"我在干嘛"的焦虑。

### Milo（视觉总监）
1. **单一珊瑚粉主色贯穿全程**，其余暖灰；进度/庆祝都用同一套色，不引入第二色相。
2. **动效是灵魂**：spring(stiffness≈300, damping≈30) 带轻微回弹，按压 scale 0.96，列表 stagger 40ms——这是"舒适感"的来源。
3. **警告**：别让"技术感"泄露到 UI（别出现命令行、日志、路径），保持纯可爱外壳。

### Nova（安卓工程师）
1. **MVP 用设备端 WebView 封装**：把 URL/HTML 塞进预置模板 APK 的 WebView，本地即可生成可安装包，无需后端。
2. **云端构建留作 Phase 2**：真正编译 Vue/PHP/复杂工程需要 Gradle 构建服务，先不做。
3. **设计令牌先落地**：先把 OKLCH 令牌转成 Compose `ColorScheme` + `Theme`，这是所有屏幕的地基。

### Sage（后端工程师）
1. **云端构建才是真能力**：PHP 必须跑服务端、Vue 必须 `npm build`，设备端 WebView 只是"壳"，不算真生成 APK。
2. **安全优先**：用户代码上云要有沙箱隔离、密钥管理（签名密钥不能落客户端）。
3. **API 契约先行**：定义 `POST /build {source, type} → 轮询 /build/{id} → 下载 /apk/{id}`。

### Remy（制作人）
1. **砍到最小**：sprint-1 只做"URL/HTML → WebView 封装预览 + 可爱 UI 地基"，Vue/PHP/云端全推迟。
2. **先有可演示物**：哪怕只是本地 WebView 包，也要能装到手机上给人看，验证"网页变 App"的价值假设。
3. **控制范围**：不碰签名发布、不上架商店，那是以后的事。

### Ivy（QA）
1. **WebView 的坑最多**：URL 失效、JS 弹窗、混合内容(mixed content)、深链接——这些要进测试矩阵。
2. **无障碍不能丢**：主色按钮对比度、焦点态、屏幕阅读器标签，按 WCAG 2.2 AA。
3. **反模式闸门**：任何偏离 `DESIGN_LANGUAGE.md` §10 的产出（尖角、硬阴影、默认字体）直接打回。
