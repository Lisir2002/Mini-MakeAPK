# Brainstorm Phase 2 — Discussion & Refinement

> 代理人实名互评，含**至少 2 处真实分歧**。

### 分歧 1：MVP 走"设备端 WebView"还是"云端真构建"？（Nova vs Sage）★真实分歧
- **Nova**：MVP 必须设备端 WebView 封装。理由：零后端、零成本、能立刻装到手机演示，验证价值假设最快；云端构建是"正确但昂贵"的事，放 Phase 2。
- **Sage**：反驳——WebView 封装对 PHP/Vue 用户是"虚假承诺"，他们粘贴 PHP 代码只会看到一个跑不起来的壳，伤害信任。应一开始就做云端真构建。
- **Kira 调解**：用户要的是"舒适"和"我的网页变成 App"。对纯 HTML/URL 用户，WebView 封装已足够惊喜；PHP/Vue 是进阶人群。先服务大多数，再补进阶。
- **Remy 裁决**：采纳 Nova 的 MVP 切片——**sprint-1 交付设备端 WebView 封装（URL/HTML）+ 云端构建 API 契约文档（Phase 2 规格）**。既快又有真东西，也诚实标注 PHP/Vue 后续支持。

### 分歧 2：首屏要不要一次性暴露三种输入（URL/HTML 上传/Vue 包）？（Kira vs Remy）★真实分歧
- **Kira**：想要"三合一"大卡片，让用户一眼看到全部可能，惊喜感强。
- **Remy**：反对。全年龄段 + 舒适 = 别让人选择困难。首屏只放一个输入框（默认 URL/HTML 粘贴），"上传工程"作为次级入口。砍复杂度。
- **Milo**：补充——即便以后多输入，也用同一套圆角卡片 + 同一珊瑚粉，视觉上不增加"技术噪音"。
- **裁决**：采纳 Remy。首屏单一输入流，进阶输入折叠到次级。

### 共识点
- 设计令牌（OKLCH→Compose）是 sprint-1 第一块地基，所有角色认同先落地。
- 动效（spring 回弹 + 可爱庆祝）是差异化，Milo 与 Kira 强烈主张，Nova 同意但要求"尊重系统'减少动效'设置"。
- 测试矩阵以 WebView 边界场景为主（Ivy），无障碍随每个屏幕走（§9 闸门）。

### 被否决的想法
- 命令行/日志式"高级模式" UI（Milo：破坏可爱外壳）。
- 首屏多 Tab 切换输入（Remy：增加认知负担）。
- 上架商店/自动签名发布（Remy：sprint-1 范围外）。
