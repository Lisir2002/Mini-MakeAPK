# Bug 处理标准作业程序（SOP）

> 适用范围：所有 bug（运行时崩溃、CI 失败、功能缺陷、性能退化等），无论大小。
> 核心思想：**每个 bug 都不只是"修好代码"，而是一次"全链路复盘 + 组织资产沉淀"**。
> 协作理念：`代码 = SOP(团队)` —— 主理人编排，成员各司其职。

---

## 0. 核心原则（硬规则）

1. **一问题一文档（One Bug, One Doc）**：每一个**独立的问题/故障**都必须有**自己独立的经验文档**（`docs/incidents/INC-<YYYYMMDD>-<slug>.md`）。**绝不可把多个不同问题的复盘塞进同一个文档**——文档按"问题"维度切分，不按"时间"或"数量"合并。
2. **同一问题的多次修复 → 同文档内 Changelog 追加**：只有"同一个 bug 的多次修复/发版"才在该文档的「更新记录」里追加；**不同 bug 必须新建独立文档**。
3. **索引与经验分离**：用 `docs/incidents/INDEX.md` 作为故障库索引，**仅放链接与一句话摘要**，真实复盘内容各自成文件，避免单文档膨胀、也便于检索与权限管理。

> 误区分警示：Changelog 是"同一 bug 的迭代史"，不是"多个 bug 的集合"。一旦判定为**新的一类问题**，立即新建 `INC-*` 文档并在 `INDEX.md` 登记，不要往旧文档里塞。

---

## 1. 标准流程（每个 bug 都走全链路）

1. **定位根因**：工程师（寇豆码）复现并定位，区分"触发"与"根本"，必要时联网交叉核实（官方 FAQ / StackOverflow / 文档）。
2. **代码修复**：工程师按最小变更原则修复，禁止绕过团队规范（如不得改 Room schema 却不写 Migration）。
3. **隐患审计（Risk Audit）**：工程师系统性排查**同类隐患**（不止于当前 bug），按严重度分级，每条给证据(`文件:行`) + 修复/预防方案（含代码）。
4. **预防策略与落地方案**：按 **预防 / 检测 / 缓解** 三桶组织，每条含可粘贴代码/配置 + 收益 + 风险点 + 关联行动项。
5. **经验教训（Lessons Learned）**：从流程 / 技术 / 协作三层总结，含"侥幸点（Where we got lucky）"。
6. **规范化经验文档**：产品经理（许清楚）联网学习业界最佳实践后执笔，格式见 §3。
7. **推送 GitHub**：主理人（齐活林）提交并推送到 `main`（文档与代码修复可同节奏或分节奏，但文档不得长期滞留本地）。
8. **QA 验证**：QA（严过关）回归测试 + 智能路由判定，确保修复不引入回归。

---

## 2. 实时更新规则（同一 bug 多次修复）

> 关键约束：**同一个 bug 的多次修复，要在每次修复提交的同时实时更新经验文档**，不得等到全部修完再补。

- 每次修复/进展后，在对应事故文档的 **「更新记录（Changelog）」** 表即时追加一行（日期 / 版本或 commit / 更新内容 / 状态）。
- 同步刷新文档内的：根因、隐患审计、预防方案、行动项（ACT-x）状态、影响版本号、整体状态（In Remediation → Closed）。
- 若 bug 跨多个 rc / 发版，每个版本节点都应在 Changelog 留痕，并保证 GitHub 上文档与代码修复版本一致。

## 3. 经验文档规范

- **格式来源**（联网学习，非凭空）：Google SRE Book《Postmortem Culture》、Atlassian《Incident Postmortem Handbook》、PagerDuty《Postmortem Template》、国内一线团队故障复盘实践。
- **写作原则**：无指责（Blameless）、事实先行、改进项必须可验证（Actionable/Specific/Time-bounded）、时间线统一时区精确到分钟、闭环跟踪、公开沉淀。
- **标准结构（10 节 + 附录）**：
  0. 更新记录（Changelog · 实时维护）
  1. 元信息（编号/标题/严重级别/状态/作者/评审/日期/影响版本）
  2. 摘要 TL;DR
  3. 时间线 Timeline（含 TTD / MTTR）
  4. 影响面 Impact
  5. 检测与响应 Detection & Response
  6. 根因分析 Root Cause（5 Whys，区分触发 vs 根本）
  7. 隐患审计 Risk Audit（按严重度）
  8. 预防策略与落地方案 Prevention（预防/检测/缓解 三桶 + 代码）
  9. 经验教训 Lessons Learned（流程/技术/协作 + 侥幸点）
  10. 行动项跟踪 Action Items（#/改进项/类型/负责人/截止/状态/验收/工单）
  - 附录（关键报错原文、参考规范链接）
- **落地路径**：每个问题独立成文件 `docs/incidents/INC-<YYYYMMDD>-<slug>.md`；所有 incident 文档在 `docs/incidents/INDEX.md` 登记链接（索引不含正文）；本 SOP 与模板置于 `docs/team/`。
- **行动项（ACT-x）**：必须含负责人 / 截止 / 验收标准 / 工单号，闭环时回写状态。
